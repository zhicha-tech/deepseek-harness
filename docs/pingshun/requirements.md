# 平顺 Buddy 需求基线（PDF 提取核对版）

> 事实来源：仓库根目录《平顺buddy-决策汇报.pdf》（17 页）。本文件由 `pdftotext` 提取第 4–13 页原文后整理；引用处保留原文措辞。第 5 页展示的 12 个细分 Buddy 属于长期扩展规划（"名单按集团和各子公司的实际业务增减——底座不变"），**本期只做六个一级 Agent**。

## 1. 产品定位（PDF 第 4 页）

> "平顺 buddy 是什么：不是聊天机器人，是会干活、能交付、守规矩的数字同事"

- **懂行**：装着国家法规、行业规范、上级文件、集团制度和"我们的写法"；每一句结论都给出出处与版本，拿不准就标"待核实"。
- **能干**：直接读写电脑里的 Word、Excel、PPT、PDF 和照片；不是给建议，而是把活干完，交出一份可以直接修改、复核的文件。
- **守规矩**：每一步留痕可追溯；成果必须由经办人和负责人复核把关；不替人做决定、不出具法定效力文件、不盖章。

## 2. 六条管理边界（PDF 第 12 页，"写进产品里的硬约束"）

1. **辅助不替代**：初稿、核对、整理由它做；判断、签字、决定永远由人做。
2. **不出法定文件**：不出具具有法定效力的文件、不盖任何印章；所有文件页脚有提示。
3. **资料不出单位**：文件在员工自己电脑上处理，不上传；涉密业务整套部署在单位内部。
4. **每一步可追溯**：谁、什么时候、用哪位 buddy、看了什么、给了什么结论，全部留痕，可审计。
5. **依据只认正式文件**：法规、规范、上级文件、集团制度以解读摘要入库并标明版本；来历不明的不作依据。
6. **单位统一管账号**：集团和各子公司各一套账户；管理员开账号、分配 buddy、看用量；人员变动当天停用。

> 与当前实现的映射：第 3、6 条涉及本地文件处理与多租户账号体系，属于部署形态决策（见 `delivery.md` 已知限制）；本期交付的单机/内网 DSH Profile 部署天然满足"文件在工作目录处理"，账号体系复用 DSH 本机 Profile，不虚构多租户 ACL。第 4 条的留痕以 DSH 会话日志（Session log）为承载。

## 3. 六个一级 Agent（PDF 第 5–11 页场景一～场景六）

六个一级 Agent 与 PDF 场景的对应：办公＝场景一（办公室）、党建＝场景二、宣传＝场景三、财务＝场景四、市场＝场景五（市场与招投标）、工程＝场景六（工程现场，覆盖施工、计量、监理、设计四组能力）。第 5 页其余八个细分 Buddy（人事、法务、审计、施工、计量、监理、设计等）**本期不做**为一级 Agent。

### A1 办公 Buddy（`ps-office`，场景一 · 办公室：讲话稿与公文）

> "从'找材料、拼框架、对格式'到'改初稿、定调子'"

- 流程：① 给出会议主题要点与往年讲话 → ② 对照上级精神与集团口径 → ③ 生成初稿，数据与引文标出处 → ④ 办公室修改，待核实项一目了然 → ⑤ 领导审定，公文格式自动校对。
- 交付物（原文）：
  - 讲话稿初稿："按集团历年文风写，结构完整，引用处可点开核对"
  - 汇报与总结材料："把分散的数据、台账、往期材料汇成一稿"
  - 请示、通知、纪要："要素齐全，格式按公文规范自动校对"
  - 待核实清单："凡是拿不准的数据与提法，单独列出，提醒核对"
- 边界（原文）："它写的是初稿，定稿永远在人手里；它做的是把资料找齐、把格式对好、把出处标清。"

### A2 党建 Buddy（`ps-party`，场景二 · 党建：学习材料、活动方案与党务台账）

> "依据只认党章党规和上级正式文件"

- 流程：① 本月主题与上级通知 → ② 对照党章党规与上级文件 → ③ 生成学习材料与活动方案 → ④ 活动后整理记录、补齐台账 → ⑤ 党支部审核、归档留痕。
- 交付物（原文）：
  - 学习材料："按主题整理原文要点与出处，不改原意、不添私货"
  - 活动方案："主题党日、'三会一课'方案初稿，流程要素齐全"
  - 会议记录："根据要点或录音整理组织生活会记录初稿"
  - 党务台账："统一格式、补齐要素，按上级检查口径自查"
- 边界（原文）："不替组织作决定，不编造学习记录；每一份材料都有正式文件做依据。"

### A3 宣传 Buddy（`ps-publicity`，场景三 · 宣传：新闻稿、公众号与汇报片脚本）

> "快稿不等于乱稿：口径统一、来源可查、发布前有人把关"

- 流程：① 项目照片与基本情况 → ② 对照集团口径与以往稿件 → ③ 新闻稿/推文多版本初稿 → ④ 敏感词与导向自检提示 → ⑤ 宣传部门审定、发布归档。
- 交付物（原文）：
  - 新闻稿："一事一稿，标题多选，数字与人名职务对照口径库"
  - 公众号推文："同一素材出不同风格版本，配图建议到位"
  - 汇报片脚本："按素材清单生成分镜与解说词初稿"
  - 口径库："统一提法、数据口径、领导职务表述，常更常新"
- 边界（原文）："它负责把稿子写快、写顺、不犯低级错误；说什么、发不发，由宣传部门决定。"

### A4 财务 Buddy（`ps-finance`，场景四 · 财务：报销核对、台账与分析）

> "不记账、不付款、不做财务判断——把该核对的地方全部标出来"

- 流程：① 报销单据与制度标准 → ② 逐项核对、标出不符点 → ③ 合同付款台账自动归集 → ④ 预算执行分析初稿 → ⑤ 财务人员复核、领导审批。
- 交付物（原文）：
  - 报销合规核对："差旅、招待、会议等标准逐项比对，不符处标红并给出依据"
  - 合同付款台账："合同、发票、付款进度自动对应，缺项提示"
  - 预算执行分析："偏差说明初稿，数据来源可追溯"
  - 制度问答："员工自助查标准，减少反复询问"
- 边界（原文）："平顺 buddy 帮财务把关前的'看'做足，签字和判断仍然在财务人员和领导手里。"

### A5 市场 Buddy（`ps-tender`，场景五 · 市场与招投标：解析、编制、自检）

> "投什么、报什么由人决定；它负责不漏项、不犯低级错误"

- 流程：① 招标文件上百页 → ② 解析资格条件、评分办法、废标项 → ③ 生成投标文件框架与自检清单 → ④ 逐项对照自检、标出缺漏 → ⑤ 经营部门定稿投标。
- 交付物（原文）：
  - 招标解析："资格、业绩、人员、评分、废标项一页看清"
  - 投标编制："商务标、技术标按模板生成初稿，证照清单自动列出"
  - 合规自检："逐条对照招标要求打钩，缺项、矛盾处标出"
  - 市场资料："客户、项目、同行信息整理成册，随时调用"
- 补充（原文）："同样的方法也适用于集团的采购评审：把招标要求与应答逐条对照，评得快、评得稳。"
- 边界：投什么、报什么由人决定。

### A6 工程 Buddy（`ps-engineering`，场景六 · 工程现场：施工、计量、监理、设计）

> "集团的看家本领，也是知识最密集的地方"

- 流程：① 报验资料拖进 buddy → ② 对照规范逐项核查 → ③ 输出《预审意见单》：缺项、疑点、出处 → ④ 资料员复核、补齐 → ⑤ 报监理，"一次通过"。
- 四组能力（原文）：
  - 施工："报验资料预审、施工方案初稿、台账治理"
  - 计量："清单比对、计量复核报告、疑点说明"
  - 监理："监理日志与旁站记录初稿、报验核查、通知单草拟"
  - 设计："校审清单、规范符合性检查"
- 边界（原文）："工程线上'对照规范逐项核查、给出出处、人来复核'的做法，正是其他业务线可以照搬的方法。"（即：结论给出出处，人来复核；不替代签章。）

## 4. 六个 Agent 的共性要求（从第 4、12 页归纳）

1. 所有结论给出来源、版本、出处；拿不准标"待核实"，来历不明的不作依据。
2. 交付"可以直接修改、复核的文件"，不是聊天建议；文件页脚有提示（不出法定文件）。
3. 判断、签字、决定、审批、发布永远由人；不盖章、不出具法定效力文件。
4. 过程留痕可审计（本期承载：DSH 会话日志与工具调用记录）。
5. 不编造事实：党建不造学习记录、宣传不造新闻事实与职务、市场不造业绩证照、工程不造现场记录、财务不造凭证。
